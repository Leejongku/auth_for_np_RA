⚠ AS-IS — 현행 방식 (매번 반복)
1
새 사업단 발령 발생
기타소속 연구원이 종합정보시스템 접속 시 권한 없음 — 업무 불가 상태
2
관리주체 부서에 프로그램별 권한 요청
교무처 학사팀·혁신융합대학총괄 등 부서별로 개별 요청 — 창구 분산, 처리 지연
3
타부서 권한이양으로 프로그램 수령
각 관리주체 부서가 타부서 권한이양 처리 — 사업단 팀장이 직접 처리
4
팀장 → 부서내 보안관리 → 구성원 개별 부여
이양받은 후 다시 팀장이 구성원 1명씩 수동 부여 — 이중 작업
📋 현행 문제점 4가지
  • ① 권한 이양 절차 이중 부담 (요청→이양→재부여)
  • ② 소속 기반 권한 제한 — 이양받아도 조회 불가 사례
  • ③ 추가 소속 권한은 정보기획팀에 또 별도 요청 필요
  • ④ 일부 사업단 팀장·차장 계정 공유 → 보안 취약
→
✅ TO-BE — 공통권한 일괄 설정 방식
1
새 사업단 발령 발생
기타소속 연구원 발령 확인 — 기존과 동일
2
정보기획팀 — 공통권한 16개 일괄 설정
부서별 공통권한부여 화면에서 16개 프로그램 한 번에 설정 — 사업단 요청 불필요
3
팀장 → 부서내 보안관리 → 구성원 부여
팀장이 기존 화면에서 그대로 부여 — 절차 단순화, 권한 이양 불필요
4
특화 프로그램만 관리주체 부서에 요청
사업단 고유 업무만 필요한 경우에 한해 별도 요청 — 요청 건수 대폭 감소
✅ 개선 효과
  • ① 신규 사업단도 즉시 공통 업무 시작 가능
  • ② 유사 사업단 간 공통 프로그램 자동 공유
  • ③ 계정 공유 필요 없음 → 보안 강화
  • ④ 정보기획팀 개별 요청 처리 부담 감소
